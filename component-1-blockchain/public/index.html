Component 1 processing flow

⚙
Cryptographic anchoring pipeline
Component 1 responsibility
01
Receive finalized records
Component 2 sends finalized academic records and their SHA-256 hashes to /blockchain/storeHash.
02
Validate SHA-256 hashes
Component 1 recalculates the hash using the canonical record format and compares it with the hash received from Component 2.
03
Generate Merkle Root
The validated record hashes are used as Merkle leaves to generate the official dataset Merkle Root.
04
Store finalized dataset on IPFS
Component 1 uploads the finalized proof manifest to IPFS and receives the CID.
05
Anchor proof on blockchain
The Merkle Root and IPFS CID are permanently anchored using the ProofStorage smart contract.
06
Maintain proof lookup index
After successful anchoring, Component 1 stores candidate + module → Merkle Root + IPFS CID in the MongoDB proof index for Component 4.
Component 1 receives finalized records from Component 2, validates the SHA-256 hashes, generates the Merkle Root, stores the finalized dataset on IPFS, anchors the Root and CID on the blockchain, and maintains the MongoDB proof index.

The candidate/module verification portal belongs to Component 4. This dashboard only demonstrates the Component 1 proof and anchoring layer.
